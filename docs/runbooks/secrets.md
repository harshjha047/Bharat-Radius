# Secrets

## Where secrets live

| Secret | Generated by | Stored | Readable by |
|---|---|---|---|
| `fr_radius*` DB password (`PGPASSWORD`), PPPoE password key (`RADIUS_PW_KEY`), Status-Server secret | `install.sh` | Ubuntu `/etc/isp-radius/<instance>.env` (0640 root:freerad) | root, FreeRADIUS |
| `app_radius*` DB password, `RADIUS_PW_KEY` copy | `install.sh` | Ubuntu `/etc/isp-radius/<instance>.app.env` (0600) → Windows `C:\isp\secrets\<env>.env` | root / Administrators, API service |
| Replicator password | `install.sh` | Ubuntu `/etc/isp-radius/replication.env` (0600) → Windows `C:\isp\secrets\pgpass.conf` | root / standby service |
| PostgreSQL CA + server cert | `install.sh` | Ubuntu `/etc/isp-radius/tls/` (CA key 0600) → Windows `C:\isp\tls\radius-ca.crt` | — |
| Mongo admin/app passwords, keyfile | `install-base.ps1` | Windows `C:\isp\secrets\mongo.env`, `mongo.keyfile` | Administrators, MongoDB service |
| JWT key, refresh pepper, field-encryption key | `install-base.ps1` | Windows `C:\isp\secrets\<env>.env` | API service |
| Router RADIUS secrets | Panel (Step 2) | MongoDB (AES-GCM) → PostgreSQL `nas.secret` | FreeRADIUS |

`RADIUS_PW_KEY` never enters the database: FreeRADIUS passes it to `radius_check()`, the API passes it to `radius_encrypt_password()`. Statement logging is disabled for both roles. Database dumps, the Windows standby and backups contain only ciphertext.

## Off-server copy (SOPS + age)

1. `age-keygen -o ~/.config/sops/age/keys.txt` on your laptop and on each VPS; put the three public keys in `.sops.yaml`.
2. `sops -e secrets/production/radius.env > secrets/production/radius.enc.env` — only `*.enc.*` files may be committed; plain files are git-ignored.
3. Keep the owner's age private key in your password manager. Losing it and both servers = re-keying every PPPoE password from the BharatRadius import.

## Rotation

| Secret | How | Downtime |
|---|---|---|
| `fr_radius` password | edit `PGPASSWORD` in `<instance>.env`, rerun `install.sh <instance>` (it applies `ALTER ROLE` and restarts FreeRADIUS) | ~1 s; routers retry |
| `app_radius` password | edit `APP_DB_PASSWORD` in `<instance>.app.env`, rerun `install.sh`, update Windows env, restart `isp-api` | API only |
| `RADIUS_PW_KEY` | `UPDATE subscribers SET password_enc = radius_encrypt_password(pgp_sym_decrypt(password_enc, :'old'), :'new')` in one transaction, then update both env files and restart FreeRADIUS + API | ~1 s |
| Router secret | change in panel (Step 2) and on the MikroTik within 30 s of each other | that router's logins during the gap |
| Leaked BharatRadius secrets (O-1) | make the repo private, rotate its DB, JWT and SMTP passwords | — |

## If a secret leaks

Rotate it immediately (table above), check `audit_logs` and PostgreSQL logs for use, purge it from git history with `git filter-repo`, force-push, and treat every clone as compromised.
